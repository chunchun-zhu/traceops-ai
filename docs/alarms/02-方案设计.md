## 实现

告警为不可覆盖事件，按 source + event_id 唯一。完全重复返回相同 id 与 duplicate=true；冲突返回 409。设备必须为台账中的用气设备，ISO 时间须带时区，统一保存 UTC。occurred_at 是业务时间，received_at 是接收时间。晚于当前时间五分钟以上拒绝。

GET /api/alarms 按 device_id/since/until/active/limit 查询。状态以 source、device_id、code 的最新事件计算；按事件时间排序，同时间按接收序号确定先后。乱序到达的旧发生事件不会复活更新的消除事件。active 查询先计算窗口终点的最新状态，再筛选发生时间；因此窗口外的旧告警不会出现在窗口内结果中。

POST /api/sessions 可携带 alarm_ids，必须为最新未消除事件。没有 device_ids 时由告警推导设备，显式设备列表须包含告警设备。发起时快照冻结，后续事件不改写原始告警。维修后通过须有同来源/设备/故障码的最新消除事件，且发生时间在本轮维修后；消除事件写入复测快照。仅勾选告警消除不能绕过已接入的事件状态。

现有接口是通用 HTTP 推送契约，没有连接真实厂商 IoT/MES。来源名称须由接入方统一映射，来源变更会形成独立事件流。API 与工作流写动作共用锁，避免在关闭校验与状态写入之间改变告警。MCP get_alarm_events 只读复用查询。
