## 修订记录

|---|---|---|

## 需求概述

基于“溯障·设备诊断与协同排障助手”从零实现设备运维核心流程。首先交付能独立运行的业务骨架，以模拟设备与资料验证公共供气异常的关联分析、依据检索、多轮反馈和交接。模型不在本次部署范围，HTTP 适配器与配置由代码提供。

## 功能需求

### P0

- 设备台账与有向供气关系导入、共同上游及影响设备查询。
- UTF-8 Markdown、TXT、文本层 PDF 解析、分块与原文位置保存。
- 知识检索按型号、版本过滤，故障码精确分流，BM25 检索和引用原文。
- LangGraph 全流程：设备确认 → 补全或证据获取 → 检查 → 原因确认 → 维修 → 复测；原生人工中断与恢复。
- 逐步记录现场反馈，更新候选状态并等待人工确认或交接。
- SQLite 会话与审计事件持久化，重启恢复，乐观版本控制。
- Web 工作台、知识库与测点页，交接 JSON 导出。

### P1

- 可选 Embedding + RRF 混合检索、HTTP 重排与 Qwen 兼容模型说明。
- 只读 stdio MCP 工具服务，业务规则配置及技能版本记录。
- 压力测点结构化录入、Docker 配置、集成测试。

## 边界与约束

首版以 FastAPI、Pydantic、LangGraph、SQLite 和原生 Web 页面运行。没有真实工厂数据、模型和历史评测集。所有预置数据标为模拟，简历的 120 份手册、800 条工单及效果指标不作为本版本成果。

不部署模型，不连接或控制设备，不接真实 IoT/MES。不在首版搭建 Elasticsearch、Neo4j、PostgreSQL、TimescaleDB、Redis、Celery、MinIO 与 OCR 服务。SQLite 拓扑查询与持久化索引提供核心功能，后续按适配边界替换。

无模型时只有规则流程和 BM25，不宣称语义诊断能力。LLM 接入后也只负责说明，不决定确认状态与流程分支。真实故障结论由人工负责。

## 验收标准

| 输入与操作 | 预期结果 |
|---|---|
| 冲压机与装配台同时气压不足 | 最近共同上游为 BR-A，显示两条连接路径及适用资料 |
| 缺少设备编号 | 进入补充信息状态，补充后继续流程 |
| 总管正常、支路异常 | 不重复总管检查，转待人工确认并保留原记录 |
| 跨不同支路的设备告警 | 共同上游为总管，分别列出各支路检查目标 |
| 无法核验，或预设检查全正常 | 转人工，不生成已确认根因 |
| 确认原因但尚未复测 | 保持待维修或待复测，不关闭 |
| 维修后全部告警设备复测通过 | 校验范围、依据、时间和告警消除后关闭 |
| 重启服务 | 原会话、引用与检查记录可载入并继续 |
| 两个页面提交旧版本反馈 | 后提交者返回 409，已保存反馈不被覆盖 |
| PDF 检索命中第二页 | 引用页码与原文字符范围对应实际解析文本 |
| 型号或版本不符 | 不返回该资料 |
| 模型接口异常或引用不存在 | 明确告知降级，不接受错误模型依据 |

## 质量要求

10 MB 文件限制，PDF 页数限制 500。测点时间必须有时区，读数单位固定 MPa。供气图导入校验方向、缺失节点和环路，整批失败不产生部分写入。API 可配置单个访问令牌；完整用户体系、租户与细粒度权限需在后续版本实现。

## 0.3 增补

页面解析与向量构建通过后台任务执行，支持取消、重试及重启恢复。告警按来源事件编号幂等接入并按事件时间计算状态，可发起会话并保留快照；有关联告警的关闭还须维修后的消除事件。复测通过必须选用有效结构化标准并冻结原文及审核记录。详见 docs/tasks、docs/alarms、docs/standards 和 event-integration.md。
