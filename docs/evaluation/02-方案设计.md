# 隔离 API 评测设计

## 修订记录

| 版本 | 日期 | 摘要 |
|---|---|---|
| v1 | 2026-10-10 | 初版 |

`EvaluationDataset` 使用 Pydantic 禁止多余字段、重复案例 ID、空集、没有标签的检索样本和未知操作。最多 200 个检索/流程案例、每流程 100 步，CLI 文件不超过 5 MB。模型输出替身为固定模式，不执行案例里的 Python、Shell 或动态表达式。

检索组共用独立临时库，每个流程独立临时目录和库。FastAPI TestClient 调用真正 API，覆盖业务校验、节点、interrupt/resume、SQLite checkpoint 与导出。重启步骤实际结束旧 lifespan 并重新建应用。临时目录在连接退出后清理，用户库路径被替换。

检索使用现有标题级口径：先取 top K 个切片，再按标题去重；Hit/Recall/MRR 只统计正样本，期待无结果的负样本单独计分。流程按状态路径预期与 HTTP 返回计分，拒绝动作还检查 revision 未变化；每个案例的所有断言均通过才算通过。

JSON 保存逐项断言、错误类型、运行耗时、数据名称/版本/类别/来源/规范化 SHA256；Markdown 便于阅读。预计与实际匹配比例不是诊断准确率，耗时不是性能基准。标题标签可能存在同名歧义，实际数据应使用唯一标题或后续扩展文档 ID 标签。

默认显式清空模型地址和密钥，CLI 关闭 LangSmith tracing。`--live-models` 才读取已有模型配置，并仍替换 DB 路径为临时库。指定替身的案例依然为 mock，逐案标记。当前评测运行 legacy 隔离模式；账号/独立审核另由集成测试覆盖，不称为线上用户权限验收。
