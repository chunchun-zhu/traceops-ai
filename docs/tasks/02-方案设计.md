## 实现

SQLite jobs 保存输入、状态、进度与结果，API 通过 /api/tasks/documents 与 /api/tasks/embeddings 返回 202。任务列表、详情、cancel、retry 共享访问令牌。服务 lifespan 启动线程 worker，数据库路径对应的 OS 文件锁选举一个执行者；其他进程等待，获得锁后才恢复旧任务。

状态为 queued → running → committing（仅资料）→ succeeded；失败为 failed，取消为 cancelled。queued 立即取消，running 在解析后或向量批次边界协作取消。入库提交阶段关闭取消，恢复后幂等重放文档导入，防止已写入资料而任务结果丢失。已完成向量批次保留，重试复用缓存；停止服务时当前模型调用完成后在批次边界恢复排队。

活跃任务按输入摘要去重；已完成任务再次提交可产生新编号，文档 fingerprint 和向量缓存保证结果幂等。失败或取消的任务可重试；模型配置变化须建立新构建任务。输入文件保存在数据库中，当前没有定期清理策略。默认上限 10 MB、PDF 500 页；文档导入提交仍有原有文本长度校验。

这是本地队列，未部署 Celery/Redis。解析阶段显示阶段进度，向量显示切片进度；不能中断正在执行的解析器或 HTTP 请求。旧同步 API 及 CLI 继续兼容。health 的 task_worker_alive 表示当前进程线程是否存活，不是分布式队列监控。
