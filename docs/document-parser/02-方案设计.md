# PDF 解析与来源设计

`document_parser.py` 按页决定文字层或 OCR 路径；`ocr.py` 提供受限 HTTP 契约；可选 `ocr_service.py` 在独立进程封装 PP-StructureV3。核心服务没有 PaddleOCR 依赖，只有用户显式启动识别进程才会初始化模型。

## 页面路径

自动模式对无文字层，或大幅图像占页面积至少 60% 且可选文字不足 80 字符的页面使用 OCR。其他页用 PyMuPDF 的表格及文字块解析。检测是启发式；有大量隐藏文字或混排扫描内容时，人员应改用全部 OCR 并核对结果。仅文字层模式遇到空页拒绝导入，有图像时给出文字缺失警告。

文字层表格保存 `rows`、外部表头标记及单元格坐标。OCR 表格将引擎 HTML 转为受限矩阵和跨度，不执行或展示原始 HTML。空/合并位置保存 null；不继承其他格的值。规范化页文本逐行使用 JSON 表示表格，不把表头自动视为第一行规则，不拼接跨页表格。

文字层按块的纵横坐标近似排序；OCR 保留引擎返回顺序。复杂多栏顺序仍须人工核对。每块记录页内字符起止，切片文字是规范化页文本的精确切片，坐标单位明确为 PDF 点或渲染像素。字符位置不是原始 PDF 的字节偏移。

## 存储与幂等

原始 PDF 存入业务库 `document_assets`，与文档、切片同事务提交，纳入成套备份。解析元数据进入文档 JSON；列表及任务结果只返回摘要。原图 API 受现有鉴权保护，根据原始 PDF 渲染当前页。

PDF 幂等键包含原文件 SHA256、业务元数据、解析模式、解析器及逐页引擎版本；不包含浮动识别文字或置信度。同配置重试复用首次成功入库的不可变结果。更换识别权重或配置时须修改模型版本标签。旧文本导入幂等方式保留。

## 任务与审核

每页开始/结束更新持久化任务进度并检查取消。识别调用正在执行时不会立即中断；返回后响应取消。所有页解析完成才提交资料，失败或取消不保存半份文档。重试重新解析整份 PDF，未实现逐页识别缓存。

标准保存来源页方法、引擎、版本及引用涉及的块。OCR 页面或表格引用要求独立审核员勾选已核对原始页图像；该确认记录进入审核快照。此记录是人员声明，不自动证明数值或条款语义正确。仅账号模式提供强制独立审核，legacy 为演示流程。

## 限额与验证

上传 10 MB、1–500 页、解析后总文本 500000 字符；表格最多 500 行和 40 列。PNG 渲染受边长、像素数和字节数限制，识别响应最多 4 MB，坐标、置信度、尺寸及跨度校验失败即拒绝。识别错误不回传服务地址、令牌或响应正文。

验证使用实际构造的文字层/扫描 PDF、HTTP 替身、识别引擎替身、真实 SQLite 与备份流程；不把替身测试当成真实 OCR 准确率测试。部署步骤及契约见 [OCR 接入指南](../ocr-integration.md)。
