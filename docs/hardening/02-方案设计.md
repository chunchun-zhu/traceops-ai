## 身份与角色

`SUZHANG_AUTH_MODE=legacy` 保持现有 Token 或本地演示；`accounts` 仅接受账号会话，原共享 Token 无权限。首位管理员由停服 CLI 交互式读取密码创建，重复初始化拒绝。

密码使用随机盐的 scrypt（N=32768、r=8、p=3），比较使用 constant-time compare；数据库只存会话 Token 的 SHA-256。Cookie 为 HttpOnly、SameSite=Strict，默认 Secure，12 小时过期；所有 Cookie 写请求及登录校验精确 Origin。账号停用、角色变化、密码重置撤销已有会话。登录失败按账号 5 次、来源 IP 30 次限制在 15 分钟窗口，数据库事务防并发绕过；反向代理默认以连接来源计数，须由可信代理层补充限流。

| 角色 | 可执行操作 |
|---|---|
| viewer | 查询、检索、查看与导出历史 |
| operator | viewer + 排障、现场读数、告警、提交标准 |
| reviewer | operator + 审核他人的标准、标准启停 |
| admin | reviewer + 资料/任务/拓扑维护、账号管理与审计 |

账号模式下确认、维修、复测的记录人由后端覆盖为登录身份，发起人和每次反馈的账号 ID 快照进入业务事件及检查点。账号管理和标准审核另有审计表，审批结果自带审核身份与说明。审计表不是外部防篡改账本；并非所有维护操作都已有独立审计事件。

## 标准审核

账号模式录入为 pending 且 inactive，客户端 approved_by 不可信。审核员核验原文、适用型号、单位和数值语义，后端再次检查资料启用与字符定位；审核冻结人员 ID、账号、姓名及说明。审核只能从 pending 进入 approved/rejected，修改需重新提交。workflow 文件锁串行化审核、启停和复测。通过复测要求 approved 与真实审核身份，历史人工标准需重新提交；已关闭历史会话保留。

## 备份与恢复

FastAPI 初始化及生命周期持有数据库对应 service 文件锁。停服备份依次获取 service、workflow、tasks 三把锁，用 SQLite backup API 导出两个数据库到暂存目录，完整性/外键/必要表及 SHA-256 校验通过后发布新目录。应用使用一个服务进程；不要设置 uvicorn 多 worker。MCP、导入脚本等拥有本地数据库权限的独立进程也必须停止，文件锁不替代操作系统访问控制。

备份包含业务资料、索引、账号密码摘要、任务输入、事件和检查点，不包含 `.env` 或模型权重。恢复复制到新目录并清除登录会话，不覆盖原库；配置 DB_PATH 指向恢复库，先验证后切换。校验和检测损坏，不证明备份来自可信方；目录需以本地权限保护。

## CI

GitHub Actions 在 Windows/Linux Python 3.13 使用依赖锁文件测试；独立 Linux job 构建非 root Docker 镜像并验收健康状态、主页和设备台账。自动化不部署、不发布镜像，也不调用真实模型。配置参考 [GitHub Python CI 文档](https://docs.github.com/en/actions/tutorials/build-and-test-code/python)；密码参数参考 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，备份 API 参考 [Python sqlite3 文档](https://docs.python.org/3/library/sqlite3.html)。
